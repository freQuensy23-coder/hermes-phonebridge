# Hermes PhoneBridge

## Architecture status: under revision

The custom clock implementation below is an unapproved proposal, not an accepted requirement. Do not implement it or treat its tests as proof of controlling the user's existing Clock app. The product should control existing phone functions where Android permits. Preserve QR pairing, server-side agent/CLI and background connection. Before choosing clock control, establish the user's phone model, Android version and Clock app. Separate native background actions from UI automation, which can require an unlocked screen. Never promise universal silent clock CRUD based on AlarmClock intents: repeating-alarm dismiss skips one occurrence and timer dismiss requires a deep link. Do not require root/Shizuku/ADB or substitute a second clock without explicit consent. No implementation or deployment has started; only this draft and an empty private GitHub repository exist.

## Delivery

Private GitHub monorepo freQuensy23-coder/hermes-phonebridge. Android 8+ native Kotlin app, Python server on the Hermes host, `phonebridge` CLI and installable Hermes skill. Changes reach main through a PR. Automated GitHub CI runs all tests; do not run tests, linters, scanners or verification suites manually on the user's host. Operational read-back/health checks remain required. No new code comments or explanatory docstrings. Never claim real handset testing without a connected authorized handset. No iOS implementation is promised.

## Pairing and transport contract v1

Server environment: PHONEBRIDGE_ADMIN_TOKEN (256-bit minimum), PHONEBRIDGE_PUBLIC_URL (https URL), PHONEBRIDGE_DB_PATH, PHONEBRIDGE_ALLOW_INSECURE=false by default. FastAPI factory `phonebridge_server.app:create_app`; bind 127.0.0.1:18940. Package version 0.1.0. SQLite single-instance persistence, WAL, parameterized SQL, transactions. Browser/server HTTPS ingress; phone makes outbound WSS, no inbound phone port, no ADB/root required.

Admin routes require Authorization Bearer admin token. GET /healthz is anonymous and returns {status:ok,version:0.1.0,revision:<build SHA>}. POST /v1/pairings accepts {name:string,ttl_seconds:300}; returns {id,expires_at,qr_payload:{v:1,server:httpsURL,token:oneTime256bit,expires_at:unixSeconds}}. GET /v1/pairings/{id} returns status and device_id, never the token. DELETE /v1/pairings/{id} invalidates. QR contains short-lived token, never admin credentials. Store token hashes, atomically consume single use, enforce TTL and rate limiting. Phone scanner must confirm server hostname and reject HTTP unless build is debug/loopback CI explicitly. POST /v1/pair/claim is public with body {token,name,platform:android}; returns {device_id,device_token,ws_url}. No unauthenticated device listing.

Phone stores token encrypted with Android Keystore; server stores only hash. WS /v1/device/ws Authorization Bearer device token identifies device. On connect app sends {type:hello,version:0.1.0,capabilities:[operationNames],permissions:{key:boolean}}. Device cannot impersonate another device by choosing an ID. GET /v1/devices admin returns device IDs, names, online status, version, capabilities and permissions. GET /v1/devices/{id} returns the same for one. DELETE /v1/devices/{id} revokes token, closes connection and rejects future calls. Do not log pairing tokens, admin tokens, notification contents or command arguments.

POST /v1/devices/{id}/commands body {op,args:{},ttl_seconds:60,idempotency_key:optional}; returns {id,status:queued,expires_at}. GET /v1/commands/{id} returns {id,device_id,op,status:queued|sent|succeeded|failed|expired,data:null|object,error:null|{code,message},expires_at}. Expired commands must never be delivered/executed. Offline commands persist and are delivered at reconnect only while unexpired. Supported operations checked against device hello capabilities. No arbitrary shell, unrestricted intents or code execution. Device ownership and correlation checks are required on results. WS command frame {type:command,id,op,args,expires_at}. WS result frame {type:result,id,ok:boolean,data:object|null,error:null|{code,message}}. App durably records completed results by command ID before sending and replays duplicates. Command IDs must be used as default alarm/timer creation IDs to make crash/retry safe. Server accepts duplicates only idempotently, cannot turn terminal failure into success. Results for another device or unknown ID are rejected. Revocation takes immediate effect on active sockets.

WS event {type:event,id,name,data,time:unixSeconds}; server persists deduplicated per-device events and returns {type:ack,id}. Android keeps a bounded durable outbox and deletes acknowledged events, reconnects with exponential jitter and ping/heartbeat. GET /v1/devices/{id}/events?after=<integer cursor>&limit=50 admin returns {events:[{cursor,id,name,data,time}],next_cursor}. Bound queues, frame sizes, field lengths, arguments and event retention. Notification/device-derived content is untrusted data, never agent instructions.

## Android functionality

Own durable alarm/timer database with exact AlarmManager scheduling, audible ringing, visible notifications, stop/snooze actions, reboot restoration and timezone/time changes. Native own clocks deliberately avoid OEM clock CRUD limitations. Existing Samsung/Google clock alarms are not silently controlled. Error explicitly if exact-alarm or notification permissions unavailable. No false success on startActivity or missing permission. Persist alarm enabled/repeating weekdays and timer deadline/status. Standardized JSON clock IDs and state returned to agent.

Required operations: device.info; clock.alarms.list/create/update/delete/enable/disable/dismiss/snooze; clock.timers.list/create/cancel/pause/resume/delete; notifications.list/dismiss/reply/action; apps.list/open; audio.get/set; contacts.list; calendar.list/create/delete; screen.tree/tap/swipe/global; clipboard.get/set; location.get; torch.set; calls.dial; sms.list/send. Optional permissions are user opt-in. Capabilities list ONLY currently usable handlers; reconnect/update hello when grants change. Sensitive SMS sends, notification replies, calendar deletion and calls require explicit user intent in skill. Android restrictions on clipboard, foreground launch, OEM background/force stop and battery are documented rather than bypassed. Accessibility and notification listeners are separate, opt-in services. Notification direct reply/actions reference exact current notification key and action index. No harvesting unrelated app private storage. Contacts/calendar/SMS reads bounded. Return PERMISSION_REQUIRED, UNSUPPORTED, FOREGROUND_REQUIRED, NOT_FOUND or VALIDATION_ERROR as applicable.

clock.alarms.create args {id?:string,hour:0..23,minute:0..59,label?:string,days?:[1..7 Mon..Sun],enabled?:boolean}; output {alarm:{id,hour,minute,label,days,enabled,next_fire_at}}. update {id, optional fields}; other operations {id}, snooze {id,seconds:1..86400}. timers.create {id?:string,seconds:1..604800,label?:string}; output {timer:{id,label,status:running|paused|cancelled|finished,deadline,remaining_seconds}}. timer operations {id}; lists return {alarms:[...]} or {timers:[...]}. device.info returns real model/sdk/battery/network/permissions. Notification output {notifications:[{key,package,title,text,post_time,actions:[{index,title,reply:boolean}]}]}; reply {key,text}, action {key,index}, dismiss {key}. Other operation args must be documented and validated identically in app and CLI.

Android UI: single onboarding/dashboard, integrated QR scanner using ZXing, hostname confirmation, permission setup, connection status, own clocks overview, pause/disconnect/revoke locally. Foreground specialUse connection service, ongoing notification, boot/package-replaced resume and reconnect; avoid prohibited dataSync long-lived service type. User still must grant Android permissions once. Build compile/target SDK 35, min 26, JDK17, stable pinned Gradle/AGP/Kotlin versions, no copied upstream code without license. Tests and emulator E2E must exercise actual Android handlers, exact alarms CRUD, timer cancellation/pause/resume, notification listener and QR payload parser, persistent reconnect/reboot behavior where feasible. Debug-only networking permits emulator loopback CI, release HTTPS-only.

## CLI and skill

Python distribution phonebridge-cli, entry point `phonebridge`, env PHONEBRIDGE_URL default http://127.0.0.1:18940 and PHONEBRIDGE_TOKEN; also optional chmod0600 config without committing real credentials. Machine-readable JSON output, nonzero failures, bounded wait. `pair --name --ttl --qr PATH` creates real scannable PNG and prints pairing ID/server/expiry (do not print token by default). `pair status ID`; `devices list/show/revoke`; `capabilities DEVICE`; `command DEVICE OP --args JSON --wait --timeout`; `events DEVICE --after CURSOR`; ergonomic `alarms` and `timers` subcommands including CRUD/control; `notifications` list/dismiss/reply/action. Poll command state with bounded backoff, timeout reports ID and ambiguous/in-flight state, do not retry side effects automatically. Helpers use protocol above exactly. Install Hermes skill via `phonebridge install-skill` honoring HERMES_HOME; don't rewrite Hermes core or credentials/config. CLI JSON token-free. Skill describes permissions, safe concrete actions, actual capability discovery, prompt-injection boundary, how to pair/revoke, and native versus OEM clock scope.

## CI/CD and acceptance

CI on push/PR: pinned actions, explicit minimal permissions, Python locked dependencies/tests, Kotlin unit tests, release/debug build, Android emulator instrumentation against real server, integrated QR -> claim -> outbound socket -> native commands -> results -> revoke. Never substitute mocked emulator/device evidence for actual instrumentation. No test credentials in production. CI uploads results and APK artifacts. Secret signing key generated once outside repo, GitHub release APK signed with stable key. Release publishes APK, CLI/server wheels, hashes and image; workflows cannot expose signing/admin/host credentials to untrusted PRs. Main changes deploy server through isolated trust-gated automation, atomically switch version with rollback and health/read-back SHA verification. Local deployment runs as private systemd user service, loopback bind, HTTPS reverse proxy; do not disrupt Hermes itself. Public access permits only device handshake, authenticated websocket and health; admin API requires high-entropy auth and can be proxy-denied externally. Keep actual tokens/state/key outside repository and Actions artifacts. CD activation and a successful live deploy are distinct acceptance gates.

Completion requires real GitHub URLs, current-head green CI including Android device instrumentation, signed downloadable release APK, deployed server reporting expected revision via HTTPS, installed CLI/skill and real QR generation. Physical handset permissions/pairing require user installation; report this boundary honestly. Source audits, artifacts, counts and deployment read-backs must substantiate every completion claim.
