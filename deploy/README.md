# PhoneBridge deployment

Deployment sources consume CI wheels only. The forced SSH entry remains `deploy <40-lowercaseSHA>`; tags, arbitrary refs and extra arguments are refused. No Git checkout, source build, sdist, package index, HTTPS provisioning, credential update or skill installation occurs in ordinary deployment.

The controller requires current main and exactly one owner-created, owner-merged same-repository PR. It authorizes the newest run for that SHA from the repository's active `.github/workflows/ci.yml` workflow ID, event push, branch main, completed successful latest attempt. All required jobs must succeed in that attempt. Jobs, artifacts, run discovery and PR discovery are paginated and bounded; check names from unrelated workflows cannot authorize deployment.

CI must publish `phonebridge-deployment-<sha>` containing root `manifest.json` and regular `wheelhouse/*.whl` files. The manifest records version 0.1.0, CPython 3.11, schema generation 1, source SHA, exact CI producer identifiers, every wheel SHA256 and the bootstrap/controller/unit/provisioner source hashes. `package_artifact.py` packages existing wheels; it never builds or downloads dependencies. The host binds GitHub artifact ID/name/digest to the successful run, verifies the manifest and Git source hashes, and extracts a bounded ZIP into an empty runtime staging directory outside the source checkout.

Parent CI builds both project wheels and downloads all runtime dependency wheels on a compatible CPython 3.11 Linux runner. The host uses the existing user-managed `~/.local/bin/python3.11` with venv/ensurepip; it does not assume Ubuntu provides `/usr/bin/python3.11`. Installation uses only local wheels with `--isolated --no-index --no-cache-dir --only-binary=:all: --require-hashes`. Universal `py3-none-any` wheels are supported; native wheels must match the host ABI/platform.

Every preparation uses a new `releases/<sha>-<uuid>` path, including same-SHA redeployments. The venv is created at its final unique path, avoiding relocated shebangs. A prepared release is never written again by deployment. Failed preparation deletes only its own candidate. Current and previous releases remain untouched until atomic symlink promotion. Old releases are retained; garbage collection is a separately authorized operation.

Previous release metadata and containment must be valid, version 0.1.0/schema generation 1 compatible, and healthy locally and publicly before promotion. Rollback restores its exact revision and checks both endpoints again. Candidate and rollback failures are retained in `last-result.json`; a failed recovery leaves `transaction.json` for a later retry. First-deployment failure removes current and stops the service.

Lock wait is 15 seconds, preparation/promotion budget 360 seconds, recovery budget 90 seconds. Subprocesses have capped timeouts and process-group cleanup. HTTPS/HTTP operations have socket and hard wall-clock limits; health requires exact nonredirecting HTTP 200 application/json, at most 4096 bytes, and status/version/revision. SIGHUP/SIGTERM/SIGINT enter rollback after promotion. SIGKILL/power loss cannot execute cleanup: the next valid forced entry recovers its durable journal before considering a new revision. No claim of immediate unattended SIGKILL recovery is made.

## Bootstrap digest lifecycle

Bootstrap is a separate parent-authorized installation/update, from reviewed source after successful automatic CI. It validates the entire key, existing restrictions, source files and target types before changing installed files. It installs `rollout.py` as the canonical `~/.local/share/phonebridge/bin/deploy_entry.py`, with no cached checkout path in the forced command. Source digests map explicitly to this renamed file, the installed user unit, and audit copies of bootstrap/provisioner. `trust.json` contains the accepted digest set. Rejected keys leave the installed controller and unit unchanged; ordinary installation errors restore prior files and reload the prior unit.

After any change to bootstrap.py, rollout.py, phonebridge.service or provision_https.py, the parent must approve and install the new digest set before CD. Application deploy rejects missing, outdated or tampered installed trust files. The installed bootstrap audit copy is not an updater: run bootstrap from the reviewed complete deploy source directory. A preexisting legacy controller cannot retrofit these checks into itself; the first cutover must replace it explicitly before enabling this CD design. Existing legacy release directory/metadata layouts must be migrated separately or treated as a separately authorized first installation.

## Stable HTTPS prerequisite

Provision HTTPS separately once after accepted CI and before application CD. `provision_https.py` works from reviewed source or its canonical installed bin directory; it restores prior site bytes, mode and enabled-link state after nginx validation/reload or ACME/final-config failure. DNS origin rejects credentials, paths, query/fragment, nonstandard ports and malformed DNS names. Successful certificate/account creation is retained on later failure; certificates are not deleted automatically. Power-loss recovery of privileged provisioning is not claimed. Ordinary deployment has no sudo/proxy/certbot path.

The parent must provision server.env, DNS/TLS/webroot, user-service enablement/linger and narrowly scoped provisioning authority through separately authorized operations. Never grant general sudo install/mv/rm/ln permissions to the restricted deployment identity. Administrative HTTP routes remain loopback-only. Shared SQLite state is not snapshotted or restored; schema generation 1 forbids an incompatible migration rollout, but source metadata alone does not prove data compatibility. Parent automatic CI must exercise real old/new server behavior against representative state.

Package/upload only on exact push/main CI; use the artifact directory itself as upload path so manifest/wheelhouse stay at ZIP root. Rerun all jobs and replace the old same-named artifact for a new attempt; partial reruns without a newly produced artifact fail closed.
